# design browser should support regular EDA file format like gate level verilog, DEF, LEF

## The LEF/DEF/verilog directory are prepared in project directory
Analyze three directory and determine how to use them.

### LEF -> lef parser. Can parser tech lef and macro lef, currently only macro lef parser is needed.
### DEF -> def parser. Parser physical information from Design Exchange Format.
### verilog -> gate level netlist parser. Use InstExtractor to quickly get instances dict
### LEF_DEF_syntax_reference.md is also provided under dev_plan, which will guide for further LEF/DEF parser development
### extractCellInfo.py under dev_plan/code_sample is provided for guiding how to generate cell_info.json by parsing LEF file. 

## New CLI
Current interface only support instance and cell json, which are generated by processing LEF, DEF and verilog. By implementing parser, now the tool supports reading EDA file directly.
Now there are three subparsers:
1. Read json, which is same to current behaviour.
2. Read verilog and lef, which does not support physical mode. Incremental json file reading is supported.
3. Read DEF and and lef, which support both physical and non-physical mode. Incremental json file reading is supported.
(2) and (3) will generated intermediate json file, which is actually the input of (1)

As built: the intermediate JSON is opt-in (`--out`), and "incremental json file reading" is
`--json FILE...` on both flows, which fills the attributes the input cannot carry (power in
practice) into the converted design - see `dev_plan/power_json_fill.md`.
